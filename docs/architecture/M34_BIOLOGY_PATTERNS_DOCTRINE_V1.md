## 2. Why M34 exists

Obsidia's historical material described cognition through living-system language (organism, blood, organs, cells, fluxes, friction, equilibrium). After SENS, B6, B7, B8, B9, M32 and M33 were separated and closed, almost every responsibility in that language is owned elsewhere. M34 exists to record, once and canonically, what survives as a structural idea, and to stop the rest from returning as runtime semantics.

M34 V1 is deliberately small: it preserves one descriptive pattern, PERTURBATION.

"Biology" in "Biology Patterns" names the genealogy and inspiration of the pattern. It does not mean biological organisms as world entities (see §11).

- Competing meaning: MASTER V2 "R7 — LIFE / BIOLOGY MODEL" (organisms, ecosystems, BodyState) — biology as a world domain, separated in §11.

## 7. Perturbation pattern

Structural form:

```
STATE → PERTURBATION → POSSIBLE TRANSITIONS → CONSTRAINTS → RESULTING STATE
```

The pattern only names conceptual positions and their order:

- an initial state concept;
- a perturbation concept that bears on it;
- possibly several possible transitions (described alternatives);
- constraints that conceptually delimit those alternatives;
- a resulting state concept that closes the form.

The historical term "stable state" is genealogy only. M34 says "resulting state" and defines no stability, equilibrium or stability metric.

"Possible transition" is a descriptive position, and:

- possible transition ≠ B8 Candidate;
- possible transition ≠ B9 CognitivePath;
- possible transition ≠ B12 selected capability or action.

"Constraint" is a descriptive position. It is not a Guard, Binder rule, KX108 decision, capability-admissibility check or validation engine. `M34_CONSTRAINT_EVALUATION=NONE`.

## 8. Description vs execution

M34 describes the shape; it never runs it. M34 does not determine which alternatives exist, which are valid, which is selected, whether a transition occurs, or whether a resulting state is good, stable or true.

M34 does not generate, select, rank, filter or execute transitions, does not apply constraints, and does not compute resulting states. There is no M34 engine and no M34 loop, and no canonical M34 operation such as reconstruct, evaluate, select, filter, apply, transition, regulate, stabilize or adapt. Any layer that performs such work does so under its own contract, never M34's.

- organ veto, Totem veto, "Judge Supreme", authority transfer;
- self-authorized or autonomous organism;
- AutoGenesis "mutate → memorize";
- fractal durable memory, organic memory;

- biological metaphor treated as proof.

## 19. Reopen protocol

M34 may be reopened only explicitly, through a new forensic and doctrine cycle with independent certification, when one of these holds:

- primary evidence provides a formal multi-scale invariant;
- feedback semantics become independently specified;
- homeostasis gains an explicit regulated variable;
- another layer requires a canonical typed representation of an M34 pattern;
- a future architecture requires executable M34 semantics.

Doctrine-only M34 must never evolve silently into a runtime.
