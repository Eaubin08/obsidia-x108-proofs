## What Obsidia X-108 Is

Obsidia X-108 is a **deterministic governance kernel** — not a model, not a framework, not a platform. It is the constitutional core of a layered agentic system.

It does not learn. It does not evolve. It decides within its invariant boundary. All other layers operate in its shadow.

---

## Infrastructure, Not Intelligence

Traditional AI infrastructure optimizes for capability. Obsidia infrastructure optimizes for **governance boundary enforcement**:

| Traditional AI Infra | Obsidia Governance Infra |
|----------------------|--------------------------|
| Maximize capability | Enforce authority boundaries |
| Best-effort output | Proof-qualified output |
| Model decides | Kernel decides, model signals |
| Memory auto-updates | Memory requires human review |
| Chain executes on trigger | Chain blocked without SovereignTicket |

---

## Key Infrastructure Properties

- **Deterministic**: Same input → same governance outcome
- **Sealed**: Kernel cannot be modified without proof chain
- **Auditable**: Every action traced through WorldActionBus
- **Bounded**: Every component has a defined authority boundary in code
- **Separable**: Any peripheral layer can be replaced; the kernel boundary holds

---

## What Obsidia Governs

- Sigma aggregation (guard, contracts, protocols)
- World action egress (WorldCallClass, Gateway)
- Memory promotion (human review required)
- Gencoin valuation (ledger only, never token)
- Proof qualification (OS3 → PoG)
- Sovereign ticket issuance

---

## What Obsidia Does Not Govern

- Free-form language model outputs (advisory signals only)
- External APIs (those require Gateway approval)
- Human decisions (those require human review)
- Real blockchain operations (explicitly blocked)

---

## Deployment Model

Obsidia is deployed as a proof core, not as a service. It has no network interface. External access is mediated through sealed interface contracts enforced in code.
