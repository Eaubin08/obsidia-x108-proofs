## Contract

PREPARE:
- non-mutating
- requires one V2_APPLY_PATCH target
- loads sealed rollback evidence (SRE)
- loads sealed apply receipt (SAR)
- cross-links SRE <-> SAR
- verifies exact preimage
- verifies current target == recorded post-patch SHA
- emits rollback_authority_hash
- KX108 invocations during rollback = 0

EXECUTE:
- requires human authorization reference
- requires exact rollback_authority_hash
- re-runs PREPARE to detect drift
- restores exact sealed preimage through Jarjar guarded restore primitive
- rechecks target SHA immediately before replace
- verifies realized restored SHA

## Important fix discovered by G5

The APPLY_PATCH execution path previously regenerated the first SRE when constructing the SAR cross-link.
Because SRE includes created_at, regenerated bytes/hash could differ from the actually stored SRE.

Fixed on G5:
- retain the exact stored SRE record
- bind SAR to that exact record/hash
- fail closed if SRE storage fails
